1. History of the Internet & World Wide Web (WWW)

1.1 Origin & Evolution of the Internet

The Internet is a global network of interconnected computers communicating via standardized communication protocols (TCP/IP). Its evolution spans several historic milestones:

  • 1969 - ARPANET (Advanced Research Projects Agency Network): Funded by the US Department of Defense (DoD). It established the first packet-switching network connecting four university nodes (UCLA, Stanford, UC Santa Barbara, and University of Utah).
  • 1983 - TCP/IP Adoption: On January 1, 1983 ("Flag Day"), ARPANET officially replaced NCP (Network Control Protocol) with the TCP/IP protocol suite, marking the true birth of the modern Internet.
  • 1986 - NSFNET: The National Science Foundation created NSFNET to connect supercomputing centers across the US, expanding academic and scientific connectivity.
  • 1990s - Commercialization: Decommissioning of ARPANET (1990) and opening of the Internet backbone to commercial ISPs (1995) created the exponential consumer explosion.
Internet vs. World Wide Web (Key Difference):
The Internet is the physical networking infrastructure (routers, optical cables, satellites, protocols) connecting millions of computers worldwide. The World Wide Web (WWW) is an information service operating on top of the Internet, allowing documents and multimedia to be interconnected via hyperlinks.

1.2 The World Wide Web (WWW)

Invented in 1989 by Sir Tim Berners-Lee at CERN (European Organization for Nuclear Research) to facilitate information sharing among scientists.

The WWW is built upon three core technological pillars:

  1. URI / URL (Uniform Resource Identifier / Locator): A universal addressing scheme used to uniquely identify and locate resources on the web (e.g., https://www.example.com/index.html).
  2. HTTP (Hypertext Transfer Protocol): The underlying application protocol defining how messages are formatted and transmitted between web clients and web servers.
  3. HTML (Hypertext Markup Language): The standard markup language used to structure web documents and establish hypertext links.
Components of a URL:
https://www.example.com:443/courses/cs/notes.html?unit=1#section2
• Scheme/Protocol: https
• Host / Domain: www.example.com
• Port: 443 (Default for HTTPS, 80 for HTTP)
• Path: /courses/cs/notes.html
• Query String: ?unit=1
• Fragment Identifier: #section2

2. HTML (HyperText Markup Language)

HTML is the skeleton of every web page. It uses predefined tags enclosed in angle brackets (<tagname>) to instruct the browser how content should be rendered.

Basic Anatomy of an HTML5 Document:

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document Title</title>
</head>
<body>
    <h1>Main Heading</h1>
    <p>This is a paragraph with a <a href="https://example.com">Hyperlink</a>.</p>
</body>
</html>
  • <!DOCTYPE html>: Informs the browser that the document is written in modern HTML5.
  • <html>: The root element of an HTML page.
  • <head>: Holds metadata, document title, character sets, external stylesheets, and scripts not directly visible in the viewport.
  • <body>: Contains all visible elements (headings, paragraphs, images, tables, forms).

3. Network & Application Protocols

Protocols define strict rules and data formats enabling diverse hardware and software platforms to communicate reliably.

3.1 HTTP (HyperText Transfer Protocol)

HTTP is an application-layer, stateless, request-response protocol running over TCP (default port 80; port 443 for encrypted HTTPS).

HTTP Methods (Verbs):

  • GET: Requests data from a specified resource without altering server state (Idempotent & Safe).
  • POST: Submits data to be processed to a specified resource (e.g., form submissions, creates new resource, Non-Idempotent).
  • PUT: Completely updates or replaces an existing target resource (Idempotent).
  • PATCH: Applies partial modifications to a resource.
  • DELETE: Deletes the specified resource.
  • HEAD: Same as GET, but transfers only the status line and header section without response body.

HTTP Status Codes:

Category Range Meaning & Common Examples
1xx Informational 100 - 199 Request received, continuing process (e.g., 101 Switching Protocols).
2xx Success 200 - 299 Action successfully received and accepted (e.g., 200 OK, 201 Created, 204 No Content).
3xx Redirection 300 - 399 Further action needed to complete request (e.g., 301 Moved Permanently, 304 Not Modified).
4xx Client Error 400 - 499 Request contains bad syntax or cannot be fulfilled (e.g., 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found).
5xx Server Error 500 - 599 Server failed to fulfill an apparently valid request (e.g., 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable).

3.2 Email Protocols: SMTP, POP3, IMAP & MIME

Email delivery requires separate protocols for sending (pushing) messages across servers and retrieving (pulling) messages to the client machine:

Protocol Full Name Port Functionality & Characteristics
SMTP Simple Mail Transfer Protocol 25, 587 (TLS), 465 (SSL) Push Protocol. Used by email clients to send outgoing messages to mail servers, and for mail servers to relay messages to destination mail servers. Text-based protocol.
POP3 Post Office Protocol version 3 110, 995 (SSL) Pull Protocol. Downloads emails from mail server to local computer and typically deletes them from the server. One-way retrieval, not suited for multiple devices.
IMAP Internet Message Access Protocol 143, 993 (SSL) Pull & Sync Protocol. Keeps emails stored on the server. Clients sync state across multiple devices (folders, read/unread status, drafts). Superior to POP3 for modern mobile/multi-device setups.
MIME Multipurpose Internet Mail Extensions N/A (Header specification) Extends standard RFC 822 7-bit ASCII email format to support non-ASCII characters, audio, video, binary attachments, and multipart message bodies using Base64 encoding.

4. Domain Name System (DNS)

DNS is the phonebook of the Internet. It is a hierarchical, distributed database system that translates human-friendly domain names (e.g., google.com) into machine-routable numerical IP addresses (e.g., 142.250.190.46).

4.1 DNS Hierarchy Structure:

  • Root Level (.): Managed by ICANN across 13 root server clusters globally.
  • Top-Level Domain (TLD) Servers: Handles extensions like .com, .org, .edu, .in, .gov.
  • Authoritative Name Servers: The final authority holding the actual DNS resource records for a specific domain.

4.2 Key DNS Record Types:

  • A Record: Maps hostname to IPv4 address (e.g., example.com → 93.184.216.34).
  • AAAA Record: Maps hostname to IPv6 address (128-bit).
  • CNAME (Canonical Name): Creates an alias pointing to another domain name (e.g., www.example.com → example.com).
  • MX (Mail Exchange): Directs incoming mail to specified mail servers for that domain.
  • NS (Name Server): Delegates a DNS zone to use given authoritative name servers.
  • TXT: Holds arbitrary text used for domain ownership validation, SPF, and DKIM email security.

5. Web Browsers & Web Servers

5.1 Web Browser Architecture:

A web browser is a client software application that retrieves, renders, and traverses information resources on the World Wide Web.

Major Components of a Browser:
1. User Interface (UI): Address bar, back/forward buttons, bookmarking menu.
2. Browser Engine: Marshals actions between the UI and the rendering engine.
3. Rendering Engine: Parses HTML & CSS to produce the visual layout on screen (e.g., Blink in Chrome/Edge, Gecko in Firefox, WebKit in Safari).
4. Networking Layer: Handles HTTP/HTTPS, DNS queries, caching, and network connections.
5. JavaScript Interpreter / Engine: Compiles and executes JS code (e.g., V8 in Chrome, SpiderMonkey in Firefox).
6. UI Backend: Draws basic widgets like windows and combo boxes using OS drawing primitives.
7. Data Storage / Persistence: LocalStorage, SessionStorage, IndexedDB, Cookies, and Cache.

5.2 Critical Rendering Path (How a Browser Renders a Page):

  1. Parse HTML markup to construct the DOM (Document Object Model) Tree.
  2. Parse CSS styles to construct the CSSOM (CSS Object Model) Tree.
  3. Combine DOM and CSSOM to create the Render Tree (containing only visible nodes).
  4. Layout (Reflow): Calculate the exact coordinates and size of each visible element on the viewport.
  5. Paint (Repaint): Rasterize and fill pixels on the screen (colors, text, borders, images).
  6. Composite: Layer ordering for hardware-accelerated rendering.

5.3 Web Server Concepts & Working:

A Web Server consists of hardware (physical computer) and software (e.g., Apache HTTP Server, Nginx, Microsoft IIS) that listens on a dedicated TCP port (80/443) and serves client requests over HTTP/HTTPS.

  • Static Web Server: Sends hosted files (HTML, CSS, images, client scripts) directly to the browser as-is without processing.
  • Dynamic Web Server: Consists of a static server plus application software and database (e.g., Node.js, PHP, Python/Django, Java Servlets). The server processes business logic, queries database, and generates customized HTML before returning it to client.
