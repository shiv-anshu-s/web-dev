1. HTML Components (Lists, Tables, Images, Forms, Frames)

1.1 Lists

HTML offers three distinct list types for structuring items:

  • Ordered Lists (<ol>): Numbered sequence (1, 2, 3 or A, B, C or I, II, III using the type attribute).
  • Unordered Lists (<ul>): Bulleted sequence (disc, circle, square).
  • Description Lists (<dl>): Key-value pair terms (<dt> for term, <dd> for description).

1.2 Tables

Tables organize tabular data into rows and columns using <table>, <tr> (table row), <th> (table header), and <td> (table data cell).

Crucial Table Attributes & Sub-elements:
• colspan="n": Merges a cell horizontally across n columns.
• rowspan="n": Merges a cell vertically across n rows.
• Semantic elements: <thead>, <tbody>, <tfoot>, and <caption>.

1.3 Images

Inserted using the empty (self-closing) tag <img>.

<img src="assets/diagram.png" alt="System Architecture Diagram" width="600" height="400" loading="lazy">

Attributes: src (path or URL), alt (accessibility alternate text and SEO), loading="lazy" (defers loading off-screen images until scrolled near viewport).

1.4 Forms

HTML Forms gather user input and transmit it to a server for processing.

<form action="/submit-data" method="POST" enctype="multipart/form-data">
    <label for="username">Username:</label>
    <input type="text" id="username" name="username" required>

    <label for="pwd">Password:</label>
    <input type="password" id="pwd" name="password" required>

    <label for="course">Course:</label>
    <select id="course" name="course">
        <option value="cse">Computer Science</option>
        <option value="it">Information Tech</option>
    </select>

    <button type="submit">Register</button>
</form>

GET vs POST Form Methods:

  • GET: Appends form parameters directly to the URL query string. Visible in address bar, cached, bookmarked, limited data size (~2048 chars). Never use for passwords.
  • POST: Sends data within the HTTP request body. Invisible in URL, not cached, no strict size limit, supports multipart file uploads.

1.5 Frames & Inline Frames (iFrames)

While legacy HTML <frameset> and <frame> tags are deprecated in HTML5 due to usability and SEO issues, modern web development relies heavily on <iframe> (Inline Frame) to embed third-party widgets, maps, videos, or documents directly into a page.

Security is reinforced via the sandbox attribute to restrict scripts, popups, and form submissions from untrusted origins.

2. Cascading Style Sheets (CSS)

CSS dictates the visual presentation, typography, colors, and responsive layouts across different screen sizes.

2.1 Three Ways to Apply CSS:

  1. Inline CSS: Applied directly inside HTML elements using style="...". High specificity, poor reusability.
  2. Internal / Embedded CSS: Placed inside <style> tags within the <head> section.
  3. External CSS: Stored in an external .css file linked via <link rel="stylesheet" href="style.css">. Best practice for maintainability and browser caching.

2.2 The CSS Box Model:

Every element in CSS is represented as a rectangular box comprising four concentric layers:

  • Content: The innermost area where text and images appear.
  • Padding: Transparent area clearing space around the content (inside border).
  • Border: Surrounds the padding and content.
  • Margin: Transparent area outside the border separating the element from its neighbors.
Total Calculated Width = Content Width + Left/Right Padding + Left/Right Border + Left/Right Margin.
Tip: Using box-sizing: border-box; ensures width includes padding and border, preventing unexpected layout overflows.

3. Dynamic HTML (DHTML) with JavaScript

DHTML (Dynamic HTML) is not a distinct programming language; rather, it is the synergistic combination of HTML + CSS + JavaScript + DOM to create interactive, animated, and responsive web pages that update without page reloads.

Core Pillars of DHTML:

  • HTML: Provides document content and structure.
  • CSS: Controls style, position, visibility, and layout.
  • JavaScript: Acts as the client-side scripting engine to implement logic.
  • DOM (Document Object Model): The programming interface exposing all HTML elements as controllable JS objects.

Event-Driven Manipulation Example:

<!-- Button dynamically altering CSS and text via DOM events -->
<div id="statusBox">Original Text</div>
<button onclick="changeStyle()">Change State</button>

<script>
function changeStyle() {
    var box = document.getElementById("statusBox");
    box.innerHTML = "Updated Dynamically via DHTML!";
    box.style.backgroundColor = "#2563eb";
    box.style.color = "#ffffff";
    box.style.padding = "10px";
}
</script>

4. Extensible Markup Language (XML), DTD & XML Schemas

XML (Extensible Markup Language) is a W3C standard designed to store and transport structured data. Unlike HTML which defines how data looks, XML defines what data is.

4.1 Well-Formed vs. Valid XML

  • Well-Formed XML: Satisfies basic syntax rules: has a single root element, all tags are properly closed and nested, tag names are case-sensitive, attribute values are quoted.
  • Valid XML: Is both well-formed AND conforms to a formal grammar definition defined in a DTD or XML Schema (XSD).

4.2 Document Type Definition (DTD)

A DTD defines the legal building blocks of an XML document (elements, attributes, nesting rules).

<!-- sample DTD definition (book.dtd) -->
<!ELEMENT library (book+)>
<!ELEMENT book (title, author, price)>
<!ELEMENT title (#PCDATA)>
<!ELEMENT author (#PCDATA)>
<!ELEMENT price (#PCDATA)>
<!ATTLIST book id CDATA #REQUIRED>

4.3 XML Schema Definition (XSD) vs DTD

Feature DTD (Document Type Definition) XML Schema (XSD)
Syntax Uses non-XML proprietary grammar syntax. Written purely in XML syntax.
Data Types Basic text types only (PCDATA, CDATA). Rich data types (integer, date, boolean, float, custom regex patterns).
Namespaces Does not support XML Namespaces. Full native support for namespaces.
Extensibility Rigid, hard to inherit or extend. Highly extensible and reusable through inheritance.

5. Presenting XML & XML Processors (DOM vs. SAX)

5.1 Presenting XML

Browsers do not have built-in styling rules for custom XML tags. XML can be presented via:

  1. CSS for XML: Linking a CSS file directly to an XML file using <?xml-stylesheet type="text/css" href="style.css"?>.
  2. XSL / XSLT (Extensible Stylesheet Language Transformations): A powerful rule-based language that transforms raw XML documents into standard HTML/XHTML before rendering in the browser.

5.2 XML Processors: DOM vs. SAX

An XML Parser (Processor) reads an XML document and provides an API for applications to access its content.

Comparison Criteria DOM (Document Object Model) Parser SAX (Simple API for XML) Parser
Processing Paradigm Tree-based: Loads the entire XML document into system memory as an in-memory hierarchical tree. Event-based: Reads XML stream sequentially from top to bottom, emitting events (startDocument, startElement, characters, endElement).
Memory Overhead High memory consumption (proportional to document size). Not recommended for huge files. Very low and constant memory footprint regardless of file size.
Navigation Bidirectional traversal (can traverse up to parent, down to children, sideways to siblings). One-way forward streaming traversal only. Cannot backtrack without re-reading.
Read / Write Supports both Reading and Modifying (node insertion, deletion, updating). Read-Only parser. Cannot manipulate or modify the XML stream directly.
Best Use Case When frequent random node access, updates, or XPATH queries are needed on moderate files. When parsing massive multi-gigabyte XML logs, mobile devices with constrained RAM, or fast one-pass reading.
